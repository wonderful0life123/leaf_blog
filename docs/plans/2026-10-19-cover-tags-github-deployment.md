# 文章封面、标签换行与 GitHub 卡片部署说明

本轮代码基于 e1541f1，沿用 runtime 发布和预热渲染器。目标提交使用本文件所在提交；文章分支仍保留生产最新文章，通过正常合并纳入代码，不能用代码分支覆盖文章分支。

## 更新范围

- Studio：文章设置可查看、更换、移除封面；标签随内容换行增高；工作台、笔记预览和编辑器支持 GitHub 卡片。
- 博客和 Studio 共用 `src/lib/github-card.mjs` 卡片结构、仓库名校验与博客样式。即时编辑保留源码和撤销行为；这不代表所有博客扩展语法都已接入编辑器。
- 后端：草稿封面存储、来源图片快照、修改状态、发布路径与私密预览同步处理封面。
- SQLite 增加 `drafts.cover` 列，schema v4 → v5。旧草稿的 NULL 表示沿用原文章封面，空字符串表示明确移除。启动迁移前代码会备份非空草稿库，部署仍应先做一致完整备份。

## 构建与切换

1. 备份配置、数据库、图片、publications、当前公开快照及可运行旧构件，记录原发布开关。无活动任务时进行切换。
2. 候选工作区使用完整匹配源码与现有锁文件；锁文件无变化，不需要为本改动更新依赖。
3. Studio 前端、`.studio-preview` 和 runtime 构件均需包含本次源码。每类构建一次即可；不要复用旧预览构件遗漏封面或新卡片结构。若部署普通静态产物，也需更新博客构建。
4. 后端更新 `store.mjs`、`catalog.mjs`、`article-status.mjs`、`publications.mjs`、`publication-content.mjs`、`article-changes.mjs`、`publication-preview.mjs`。渲染器由 `publication-renderer.ts` 构建；使用完整源码候选工作区避免漏文件。
5. `.studio-preview` 放在能解析匹配依赖的位置，使用服务账号验证模块加载。不能重复此前“符号链接真实路径祖先没有 node_modules”的部署布局。
6. 代码基准、runtime 构件、公开快照及 Studio 配置保持一致；保留最新生产文章与目录数据。后端重启触发增加式迁移并预热，检查迁移和预热完成后按原状态恢复发布入口。

## 针对性验收

- `node --test --test-concurrency=1 tests/studio/*.test.mjs`；构建预览构件后再运行。HTTP 用例需要本地监听权限。
- `node tests/studio/runtime-publish.smoke.mjs` 使用隔离数据和本地裸 Git，不替用户发布文章。
- 封面上传、刷新、替换、移除；已有相对路径封面保留；封面与目录一起移动后图片仍正确。
- 桌面/手机的长标签显示、保存恢复；GitHub 卡片点击编辑、移开恢复、源码不被改写。代码块内、转义及非法仓库名不识别为卡片。
- 私密预览封面实际加载后，同路径匿名访问仍须 401/no-store。私密预览禁用脚本，所以 GitHub 卡片显示仓库链接和静态占位信息；动态仓库数据在编辑器阅读界面及公开博客请求 GitHub API。
- GitHub API 不可用时卡片仍有仓库名和链接，不阻塞写作；未作所有扩展语法均兼容的承诺。

回滚优先保留当前私密数据。增加式 schema 不应通过旧数据库覆盖回滚；若新版本已保存封面，旧界面不会编辑新字段，回滚后应暂停发布并核对差异再恢复。此说明不授权生产真实发布。
