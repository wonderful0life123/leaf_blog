## 服务器执行范围

1. 核对并记录当前代码 SHA、文章分支 HEAD、活动内容快照及三个服务的实际部署目录；从 service 配置读取路径，不猜测。检查磁盘能容纳候选构件、备份及上一版。若不足，先报告具体差额，不自动删除共享缓存、容器或历史备份。
2. 暂停新发布，等待当前任务结束；若已有部分成功/待重试任务，先恢复原任务，不能直接升级并丢弃任务。生成一次最新完整私密备份，包含数据库、图片、organization/undo、publications；记录当前运行构件及内容版本。
3. 在独立工作区检出目标代码，保留线上最新文章提交。代码与文章分支必须兼容，不强推，不覆盖线上文章；遇到真实冲突再报告。按锁文件安装依赖，新增直接依赖为 github-slugger 和 mdast-util-from-markdown，使用仓库声明的包管理器版本。
4. 以同一候选代码构建普通博客、Studio、runtime 和私密预览。共享依赖相同且私密预览已由构建脚本生成时，不重复编译它。更新匹配的发布后台、共享 src/lib、运行时和独立发布仓库基准。保持私密构件不进入公开目录。
5. Studio 启动执行增加式 SQLite v4 迁移：增加文章身份/绑定，不改变草稿正文、标签、回收站或期望目录。重启前后核对 schema、integrity_check、草稿/图片数量和内容摘要、organization/undo。保留 OAuth、环境配置、Nginx、TLS、CDN、笔记仓库及旧部署 timer 原状态。
6. 用当前文章生成新的 runtime 候选内容快照；保留最新公开目录映射与历史路由清单，不用本地空文件覆盖已有公开内容。按既有原子流程切换匹配构件；仅重启实际受后台/运行时升级影响的服务，不重启 Nginx。
7. 恢复升级前的发布开关意图，不代用户发布文章或应用正式目录调整。目录确认后才对 GitHub 和公开网站生效，部署本身不得触发批量移动。

## 一次针对性验收即可

- 一次隔离数据演练：将含相对图片的中文 Markdown 移动到中文目录；本地裸 Git 旧文件删除、新文件唯一；代码示例不变、图片字节不变；新址 200，旧址 302/no-store，移回后无循环；不包含私人草稿正文。
- 公网默认入口及当前 DNS 节点抽查：首页、一篇既有文章和其图片、归档、Studio、新前端资源。比对内容/哈希，不只检查 200。无需逐一遍历失效历史节点。
- 认证私密预览后以完全相同路径匿名请求 HTML、图片、任务接口，均应拒绝且 no-store。保留已有 CDN 规则；出现真实异常再扩大检查。
- 用户本人确认一次正式目录调整后，再核对 GitHub 新旧路径、公开目录及跳转。这一步不能用隔离测试冒充。

记录阶段耗时、目标 SHA、迁移摘要、验收结果和回滚位置即可，不重复全站构建或全部历史检查。不承诺服务器耗时等于本机测试耗时。

## 恢复边界

如果文章提交已经推送或新内容已经公开，优先重试原任务完成切换/绑定确认。不能直接恢复旧数据库覆盖新草稿，不能强推撤回文章，也不能切回缺少新文章或历史跳转的旧静态快照。
