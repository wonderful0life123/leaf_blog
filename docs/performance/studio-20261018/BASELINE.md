# Studio 交互性能基线（2026-10-18）

本轮是测量与问题定位，不是优化效果报告。代码基准 `8d106a3331ebe8991e5c23a29408860c8ee0602e`，分支 `feat/studio-reading-workbench`。没有修改业务源码、推送、部署或写入线上文章。

## 环境与方法

- macOS 本机，Node v22.23.2，生产 Studio 构建（7.01 秒），实际 Studio 后端和 SQLite。
- 本机 127.0.0.1:4341，独立数据库、24 篇合成文章，3 篇导入为测试草稿；OAuth 上游模拟，发布关闭。未复制生产数据库。
- Codex 应用内浏览器，852 × 864 CSS 像素；不是用户 Chrome 生产会话，也不是手机或弱 CPU 测试。
- 3 种正文：440 字符短文、13,670 字符中文正文、17,681 字符/100 个 JavaScript 代码块。
- 在真实编辑器中连续键入 ASCII 字符，比较即时渲染与源码；不是中文输入法组合输入。每组 33 个 beforeinput 样本，代码即时渲染复测共 66 个。未做 CPU/网络降速。
- 临时 HTML shell 加载诊断脚本；业务 JS/CSS 使用同一生产构建。脚本采样 beforeinput/click 到第二次 requestAnimationFrame 的时间、长任务和 fetch 响应头时间，将记录发送到本机诊断端点。
- **两次 rAF 是响应代理指标，不是实际屏幕呈现时间、INP 或用户键盘到显示的端到端延迟。** 自动化、窗口状态及诊断代码可能影响结果；不将工具调用耗时当作网站耗时。
- 抽样观察到合成测试服务器未提供公共日历/Pagefind 端点，相关脚本报错；音乐列表仍有外部加载。该环境不能用于判断公网首屏、完整博客功能或生产网络问题。

## 切换和保存

- 工作台文章切换，每类 4 次 click→两次 rAF：短文中位数 34.4 ms，万字正文 42.65 ms，代码文章 125.85 ms（最大 135.8 ms）。不保证异步语法高亮全部完成；后续应测内容就绪信号。
- 返回工作台 3 次：中位数 49.5 ms，单次最大 324.7 ms。后者发生在复杂代码文章之后，样本不足，尚不能归因。
- 7 次自动保存请求均成功。浏览器 fetch 到响应头 11–35.7 ms；后端请求开始到 response finish 中位数 15.37 ms、最大 33.3 ms。
- 保存前应用有 600 ms 防抖，该等待不包括在上述网络请求耗时中。没有测“最后一次输入→已保存提示”的完整耗时。
- SQLite 核查：3 条隔离草稿 revision 分别为 3、3、4；键入后缀保留，页面刷新后代码文章仍有完整后缀、总长 17,781 字符。未出现保存错误或冲突。

## 翻页/滚动探索

代码文章即时渲染模式执行两轮各 8 次 PageDown，再用源码模式做一轮。位置与保存状态正常。滚动期间 rAF 最大间隔约 190–206 ms，源码对照也出现约 195 ms；跳回开头/模式切换也有类似峰值。

这只能作为复现线索：自动化按键含光标移动、页面测量与工具读取干扰，不能视为纯触控板滚动帧率，也不能证明即时渲染是滚动卡顿主因。需要同环境、独立手势和性能轨迹进一步归因。

## 源码与 DOM 证据

1. `Studio.svelte:170` 无条件计算当前文章完整 Markdown 预览；即时渲染/源码模式仍走 `marked.parse`、DOMParser 和净化/公式遍历。这是可以验证的无效工作候选，尚未通过消融试验证明收益。
2. `live-markdown.mjs:11` 每次正文变化完整解析 `livePlan`；纯 Node 热态 100 次测量的中位数分别为 0.05、1.16、0.73 ms。**单独解析在本机很快，不宜直接宣布解析器是主瓶颈**；此测试不包含装饰、DOM、布局和绘制。
3. `ArticleWorkbench.svelte:112` 切换文章重新生成 HTML；`reading-code.mjs` 对正文内所有代码块建立控制栏并异步高亮，没有按视口延后。代码文章切换较慢与此相符，因果需后续 A/B 验证。
4. 代码文章工作台观测到约 18,384 个 DOM 节点，阅读区约 5,117；多个 aria-label=音乐 的容器各包含数千节点。容器可能嵌套，不能直接相加。音乐视图开销是候选项，不能据此归因所有卡顿。
5. 后端 catalog 扫描和发布内容比较在请求路径中存在重复工作；本轮本地保存样本未显示它是最紧急瓶颈，生产磁盘/CPU情况不能由本机结果推断。

## 建议下一轮范围

先保留现有即时渲染、代码复制、撤销重做、自动保存和恢复语义，验证两类局部改动：未显示的整篇预览按需计算；文章切换时复用未变内容并把不可见代码高亮延后。每项单独与本基线对照，收益不明显则不保留。音乐列表惰性加载另测，不直接删除用户功能。

先量化响应和功能正确性，不承诺“极致”或固定倍数；滚动、中文 IME、线上冷启动仍未完成专项验收。
