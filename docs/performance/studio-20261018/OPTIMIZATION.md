基于 `8d106a3331ebe8991e5c23a29408860c8ee0602e`，分支 `feat/studio-reading-workbench`。未提交、推送或部署；未访问/修改生产草稿。本轮只处理隐藏预览和阅读区代码高亮，不涉及发布后端、目录数据模型或公开博客。

## 结果

同一台机器、852 × 864 应用内浏览器、生产 Studio 构建及独立 SQLite。沿用 BASELINE.md 的三份合成正文。切换指标仍为点击到第二次 requestAnimationFrame，**不是 INP、实际绘制完成或公网端到端耗时**。

| 工作台切换（各取首 4 次） | 改前中位数 | 改后中位数 | 改后最大值 |
|---|---:|---:|---:|
| 短文，440 字符 | 34.4 ms | 34.4 ms | 39.6 ms |
| 中文正文，13,670 字符 | 42.65 ms | 39.7 ms | 40.0 ms |
| 100 个代码块，17,681 字符 | 125.85 ms | 59.05 ms | 61.2 ms |

代码文章此项代理耗时降低约 53%。样本较少，只证明此工作负载的局部改善。初次可视位置的阅读区 DOM 从约 5,117 个节点降到 1,057 个；100 个代码块原文和复制控件仍全部存在，起初只为 1 个接近视口的块创建高亮 span。滚到末尾后第 100 个代码块正常高亮，原文完整。

中间试验只做隐藏预览/缓存时，代码文章切换中位数约 122.8 ms（3 次），相对原先改善很小；加入按视口高亮后才有上述下降。不能把全部收益归给 Markdown 缓存。

## 改动

- `WritingEditor.svelte` 只在分屏或预览模式调用完整 Markdown 渲染；即时渲染继续使用现有 CodeMirror 装饰。
- `Studio.svelte` 使用实例内有界 HTML 缓存。最多 8 项，键与 HTML 合计最多 1,000,000 字符；正文、文章位置、附件变化按新键重算，素材目录对象更新清空。超大结果不进入缓存，不写浏览器持久存储。
- `reading-code.mjs` 立即创建代码文字、行号、复制控件；接近视口才做语法高亮。不支持 IntersectionObserver 时使用原立即高亮路径。切换/销毁断开观察器，异步结果受渲染代数和 DOM 连接状态保护。
- 未新增依赖；Markdown 净化、公式渲染、图片解析规则不变。
