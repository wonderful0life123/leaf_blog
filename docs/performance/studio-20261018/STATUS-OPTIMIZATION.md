# 草稿加载、保存与状态判断（本地，未推送）

2026-10-18。本轮承接前三轮前端优化，范围限定为服务器侧状态判断；没有修改前端、数据库结构、保存版本检查或发布流程。

## 定位与处理

隔离样本中，列表的大部分处理时间用于 `contentComparison` 反复解析每份草稿及其已发布原文。24 篇文章、18 份编辑副本、40 份历史任务的第一次定位测量中，列表约 59ms，单独正文比较约 54ms。

另外，`decorate` 读取一次任务列表后，`catalogItems` 和正文比较各自通过 `currentPosts` 再读一次。生产服务已经有当前 `sourceRoots.blog`，这些额外读取不会改变所选目录。

处理方式：

- 每个 `openPublications` 实例持有正文语法缓存。按正文文本精确匹配，最多 128 项，正文和去除位置字段后的语法树 JSON 合计最多 4,000,000 个字符；超大正文不驻留。此上限是记账字符量，不是精确的进程内存字节数。
- 只缓存解析后的语法树。每次请求仍重新读取源目录、任务和绑定，重新解析引用关系并计算当前图片摘要，不缓存最终状态、图片摘要或目录扫描结果。
- `currentPosts` 有明确当前根目录时直接使用，不再读取无用的发布记录；没有根目录时保留原回退逻辑。

## 最终对比

Node 22.23.2，同一台本机，真实 SQLite 与 `createHandler` 路由。每篇合成文章约 8,840 字符，含 40 个小节、40 个代码块和一张共享 256KiB 图片。每个操作执行 14 次，前 2 次用于预热，统计随后 12 次中位数。

基线使用本轮修改前的两个后端模块副本，其他模块与当前代码一致。数据只写临时隔离目录；发布关闭，没有 GitHub/CDN 请求。请求直接进入路由处理器，包含正文读取、状态判断和 JSON 序列化，**不包含认证、TCP、浏览器、网络传输和页面渲染时间**。真实 HTTP/认证覆盖在独立回归测试中。

## 正确性与范围

58 项独立测试通过：server、publications、article-status-cache、store、organization。覆盖真实 HTTP 的认证与匿名拒绝、保存冲突、实际本地裸 Git 发布演练、目录移动、恢复原文后的状态、引用式 Markdown 和图片映射变化。

新增缓存测试还验证：

- LRU、容量限制及超大正文不驻留。
- 修改原文后立即更新状态，恢复原文后状态恢复。
- 同一路径图片即使字节数和修改时间相同，内容变化也能被发现；丢失图片不能误判一致。
- 当前文章来源切换、文章绑定变化和私有图片映射变化不会复用过期判断。

新增测试文件 Biome 检查、两个修改模块的 Node 语法检查和 `git diff --check` 通过。本轮没有前端改动，不重复前端构建或浏览器布局验收。测试只使用隔离数据，没有发布、部署或迁移用户数据。

## 尚未优化

目录接口仍可能读取两次文章目录；列表、目录及单篇接口仍各自读取文件。缓存被大量不同版本正文挤出后收益会下降。后续应根据线上请求耗时决定是否值得处理扫描重复，不引入依赖时间戳的状态缓存。

以上数字不能代替线上服务器、GitHub/CDN、访客页面或构建部署性能。服务器部署后应分别复测这些链路，保留首次请求与重复请求的区别。
