# 快速发布完整流程：隔离集成结果

> 历史实验记录。已由正式实现替代，原临时脚本已移除。当前入口为 `pnpm runtime:build` 与 `pnpm runtime:test`；部署及兼容边界见 [RUNTIME_PUBLISHING.md](../../deploy/studio/RUNTIME_PUBLISHING.md)。以下耗时与说明对应实验当时的版本。

2026-10-15。已接入现有 Studio 的 HTTP handler、SQLite store、publication manager、Git publisher 和原子部署逻辑，以实验 adapter 替换确认后的全站构建。生产配置不会选择这个 adapter，本次没有修改正式发布行为、推送 GitHub 或部署服务器。

## 实测

一次 Astro 生产构建 9.140 秒，此后同一 Node 进程运行所有发布场景，编译产物哈希不变。

| 场景 | 生成私密预览 | 确认发布到完成 | 含预览及公开 HTTP 检查 |
| --- | ---: | ---: | ---: |
| 首次发布 | 678 ms | 672 ms | 1,722 ms |
| 修改正文、标题、分类 | 349 ms | 629 ms | 1,202 ms |

以上是本机单轮数据，不是服务器承诺或 p95。确认耗时包括真实 Git commit/push 到本地裸仓库、内容快照、RSS/站点地图、Pagefind 索引生成和原子切换；不包含 GitHub 网络和公网 CDN。源码复制、首次依赖准备及代码构建不计入内容发布耗时。原始阶段记录见 [pipeline-results.json](./pipeline-results.json)。

## 已验证的流程

1. 通过现有 HTTP 接口生成真实私密预览，预览阶段不推送。
2. 明确确认后，从审核过的任务工作区生成已发布内容快照、图片、RSS、站点地图与 Pagefind 搜索包。
3. 现有 Git publisher 只提交文章及引用图片；推送成功后统一切换内容版本。
4. 真实博客模板读取新版本，首页、归档数据、文章、RSS、站点地图与图片一致。公开服务不直接暴露原始 published.json；其他未发布草稿不进入快照或搜索。
5. 同一 HTTP 响应中的集合读取由 AsyncLocalStorage 固定到同一不可变版本，避免切换过程中混用新旧内容。
6. 搜索包和媒体使用带版本的 URL；旧包保留，已经发出的请求可以继续读取。HTML 与搜索版本入口使用 no-store。浏览器里的搜索代理每次查询核对当前版本，不需要重新加载页面。

Pagefind 使用其[官方 Node API](https://pagefind.app/docs/node-api/)直接建立内容索引，无需先编译全站 HTML。运行时页面沿用 [Astro 按需渲染](https://docs.astro.build/en/guides/on-demand-rendering/)及前一轮已验证的 live collection。

## 失败与重试

隔离流程实际执行了以下断言：

- 重复确认：进行中拒绝重复操作，已完成时返回同一结果。
- 本地 Git 远端真实 pre-receive hook 拒绝推送：公开版本保持不变；重建 manager 后重试沿用原提交。
- 推送成功但切换前发生异常：保留旧公开内容；重试不产生额外提交。
- 准备发布内容期间修改草稿：停止提交和上线。
- 预览后远端出现真实新提交：拒绝旧预览上线。
- 新版媒体和搜索包可访问，旧版本资源仍可访问；仓库原工作区不被写入。

专项测试及现有发布状态测试合计 16/16 通过。浏览器确认了正文、代码、公式和真实搜索框；搜索命中新版正文。另在前一轮相同搜索代理上进行本地版本回切/恢复：同一个页面未刷新即可查询 FIRST 和 UPDATED 两个不同索引。最终轮修复了搜索摘要夹带代码 HTML 标签的问题，并再次检查查询结果。

## 复现

```sh
node experiments/live-publishing/run.mjs --pipeline
node --test experiments/live-publishing/release.test.mjs tests/studio/publications.test.mjs
```

浏览器检查时加 `--serve`，实际地址在输出中。发送 SIGTERM 可关闭该临时服务；不影响 4321 上的原 Studio。每轮输出独立临时目录、构建日志、任务日志和 pipeline-results.json，不触碰生产数据。Git 远端被强制设置并断言为临时本地裸仓库。

## 尚不能直接部署为生产版本

本轮完成了隔离集成，保留以下明确边界：

- **真实交付**：没有测试 GitHub 网络、线上 Nginx 或 CDN。公开 HTML、RSS、版本入口需要遵守不缓存/再验证策略；现有 CDN 不能假定自动遵守响应头。图片和搜索包可长期缓存。线上缓存规则应在切换前验证。
- **功能一致性**：实验 RSS 只包含摘要，尚未恢复现有全文订阅；站点地图静态 URL 清单暂为实验值。需要接入正式站点配置，覆盖分页和所有公开静态页面。已发布 MDX、加密文章明确拒绝，图片暂为原始文件，没有接入 Astro 图片优化。测试图片仅为 1×1 PNG。
- **生产入口**：仍通过实验脚本临时适配主题路由，不是正式配置开关。实验使用 trailingSlash=ignore 便于动态资源路由；正式接入必须保留现有文章 URL 的规范化规则。普通静态页面上的构建时统计、完整主题功能、元数据 schema 和高并发负载仍需兼容检查。
- **故障边界**：测试了 manager 重建后的重试，没有模拟断电、文件系统损坏或多发布服务实例。Git 提交已经推送后，回切公开内容不会撤销该提交；报告和 UI 必须区分“已推送”和“已上线”。

下一步应把实验 adapter、运行时数据入口、资源路由整理成默认关闭的正式运行模式，补齐以上功能一致性要求，再在服务器旁路实例上验证；之后才能让现有发布按钮使用它。日常内容更新免全站构建，主题/功能代码部署仍需要构建。
