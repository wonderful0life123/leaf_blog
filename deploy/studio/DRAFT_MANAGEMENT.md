# 草稿管理部署与验收

本次包含前端和后端更新，不能只更新 studio-dist。后端改动仅在 `scripts/studio/store.mjs` 和 `scripts/studio/http.mjs`；OAuth 实现、环境配置、Nginx 和图片格式不变。需要重启 Studio 服务，数据库从 v1 增量升级到 v2。

## 部署顺序

1. 在独立 checkout 获取交接提交，安装锁定依赖，运行 `pnpm run studio:test`、`pnpm build`、`pnpm run studio:build`。
2. 记录当前后端文件、前端产物、服务环境和数据库版本，备份现有代码及配置。保留服务器尚未提交的 OAuth/网络修复；不得用仓库版本覆盖这些改动，不要记录密钥值。
3. 先在私有临时目录用一致性数据库副本演练升级，核对草稿数量、正文和附件引用。数据库内的实际内容不要写入公开日志。
4. 安排短暂写作维护窗口。停止 Studio 服务后完整备份数据库目录（含可能存在的 WAL/SHM）、前后端版本。不要用本机测试库覆盖线上数据库。
5. 更新运行目录里的 `store.mjs` 和 `http.mjs`，以及对应的 Studio 前端产物。普通 dist 和 studio-dist 分别部署到原有目录，不得混入公开目录。其他后端文件及 OAuth/网络修复保留。
6. 启动 Studio。首次打开数据库会先保存 v1 一致性快照（有草稿时），再为 drafts 增加 nullable `deleted_at` 列并设 `user_version=2`。原正文、图片、ID 和 revision 不变；不能仅凭启动成功认为迁移已验收。
7. 核对升级前后草稿数量、图片读取、登录会话及服务权限，执行以下验收，再结束维护窗口。不得合并 master、修改 `/root/Firefly` 或启用旧 timer。

## 验收

- 已登录新建草稿，编辑标题、正文、分类和标签；自动保存后返回列表，摘要与更新时间刷新。
- 用仅出现在正文中的词搜索；检查最近修改、最近创建和标题排序。
- 复制含图片的草稿，独立修改副本，原稿不变；副本图片在刷新后可见。
- 移入回收站后正常列表消失，回收站保留；刷新及服务重启后仍在。
- 恢复后可继续编辑，正文和图片完整。
- 两个页面打开同一草稿，一个页面删除后，旧页面保存必须显示冲突，不能自动复活或覆盖草稿。
- 彻底删除只对回收站草稿开放，必须先显示确认弹窗；用明确可丢弃的验收草稿确认测试。共用图片不能被误删。
- 匿名读取回收站、复制/删除/恢复/彻底删除均被拒绝；跨站写请求被拒绝。
- 手机尺寸下搜索、排序和每行操作可见可用；列表滚动、导航及分屏功能不回归。

## 数据边界与回滚

回收站不自动清空。同一来源的导入草稿在回收站期间仍保留来源关联，再次导入会提示先恢复。复制为独立草稿，不关联笔记来源。

彻底删除移除草稿记录，图片可能被其他草稿共用，因此不进行图片垃圾回收；已有备份也保留原定保留策略。这不是安全擦除功能。

旧后端不理解 v2 回收站，不能直接回退旧后端并继续使用 v2 数据库。若在维护验收期间失败、尚无新用户写入，可停服务后成套恢复升级前的后端、前端和数据库备份。若已产生新写入，先保存当前一致性快照并列出差异，再制定保留新草稿的修复或回滚方案；不得直接覆盖为旧库而丢失新内容。

报告需注明实际前端提交、两个后端文件哈希、保留的服务器修复、迁移前后版本/数量、重启状态、验收范围和回滚位置。
