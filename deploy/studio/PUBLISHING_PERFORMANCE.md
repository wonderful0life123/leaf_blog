# 日常发布构建优化（2026-10-14）

> 本文记录前一阶段静态构建优化。当前可选的免整站编译发布方式及部署流程见 [RUNTIME_PUBLISHING.md](./RUNTIME_PUBLISHING.md)。

本轮基于已发布 `server-codex-setup.md` 的内容提交 `d90314a`，工作分支为 `perf/studio-daily-publishing`。只调整构建依赖范围，不修改发布后台、数据库、OAuth、Git 提交规则或原子上线流程。

## 改动

- Studio 页面移至 `src/components/studio/StudioPage.astro`，通过 Astro `injectRoute` 仅在独立 Studio 构建及显式启用的本地开发中注册。公开构建不再编译编辑器；仅让 `getStaticPaths()` 返回空数组并不能阻止其依赖参与编译。
- 文章页分享海报的图片查找只匹配图片扩展名，不再使用匹配所有源码的 `../../**`。
- 构建时从组件、配置和 MDX 中收集图标名称，避免将约 21 MB 的全部已安装图标集放入构建模块。开发模式仍保留全部图标。已知前缀的动态图标名保留整套集合；如果未来使用完全计算得到的图标名称，在 `iconIncludes(root, extra)` 的 `extra` 中显式保留需要的集合或图标。

首页、归档、分类、RSS、站点地图和 Pagefind 仍重新生成；没有把单篇私密预览当作上线产物，也没有启用额外后台服务或新的持久缓存。

## 本地实测

相同机器、相同测试文章（代码、公式和一张 PNG）、本地裸 Git remote、隔离草稿库和上线目录。第二次发布修改正文。通过真实发布后台执行编译、提交、推送和原子切换。

| 场景 | 修改前总耗时 | 修改后总耗时 | 修改前 site | 修改后 site |
| --- | ---: | ---: | ---: | ---: |
| 首次发布 | 14.032 s | 10.691 s | 12.404 s | 9.154 s |
| 修改正文再发布 | 12.375 s | 9.125 s | 10.876 s | 7.624 s |

两次完整流程分别缩短约 24% 和 26%。单独公开构建的诊断样本为约 11.7 → 6.5 秒；完整发布使用全新的隔离工作目录，因此不应拿单独构建数字当作真实发布总耗时。

这些是本地样本，不是生产时延承诺。用户提供的服务器基线为 site 160 秒、build 162 秒，尚待服务器以同一测试文章复测。静态站点依然需要全站构建，本轮不能保证“点击后几秒上线”。

## 验证与复现

- `pnpm run studio:test`：91/91 通过。
- `pnpm build`、`pnpm run studio:build`：通过；独立 Studio 仍包含 `/studio/` 页面、编辑器 hydration 和 `/studio-static/` 资源。
- 图标精简前后，19 个公开页面共 2,019 个生成 SVG 逐项相同。
- `node tests/studio/publication-build.smoke.mjs --worktree`：两次真实本地发布通过；验证首页、归档、RSS、站点地图引用新文章，正文第二次更新，数学公式与代码保留，Pagefind 产物存在，公开产物无 Studio 编辑器和私密目录。

已提交代码的独立 checkout 使用 `node tests/studio/publication-build.smoke.mjs` 即可。`--worktree` 仅用于本地验证未提交改动：将 Git 可见文件复制到临时克隆并在其中生成测试提交，不改原仓库索引，不包含被忽略的私密数据，不推送 GitHub。两次发布已在同一命令内覆盖，无需另跑多份相同演练。基准测试期间避免并行构建和浏览器压测。

本轮没有部署服务器。部署生效依赖独立发布仓库及 `WONDER_PUBLISH_CODE_REVISION` 同步到最终提交；仅替换网页 dist 不会加速以后发布时使用的旧代码。双前端仍各自构建，私密预览构件按对应代码基准生成。无需重新迁移数据库或覆盖已有后端/OAuth 修复。
