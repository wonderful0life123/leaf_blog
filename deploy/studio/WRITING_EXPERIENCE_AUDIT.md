# 写作体验验收 · 第一轮

日期：2026-10-13。分支：`feat/studio-writing-experience`，起点为 `d5be3e26c0b94830bfdc6f5830adcafdf9e80a64`。仅本地验收，未推送或部署。

目标：以 Obsidian 的 Markdown 编辑习惯为参考，先验证连续写作，再决定是否更换编辑器。并非完整复刻 Obsidian；当前保留 CodeMirror、现有博客配色、草稿 API 和发布流程。

## 已修复

| 操作 | 修复前实际结果 | 本轮行为 |
| --- | --- | --- |
| 选中文字，连续点两次加粗 | `****技术笔记****`，不断叠加符号 | 第二次取消加粗，选区与撤销保留；斜体、删除线和行内代码使用相同规则 |
| 插入代码块后直接输入 | 输入落在结束围栏下面 | 选中块内占位内容，输入即可替换；公式同样处理 |
| 第一项末尾连续按两次回车 | 自动在第二项前加空行，仍残留 `2. ` | 空项回车直接退出；编号、无序和待办列表共用规则 |

格式切换使用 Markdown 语法树识别定界符，避免把粗体的星号当作斜体删除。列表调整使用 CodeMirror 的 `nonTightLists:false`；同时关闭语言扩展自动注册的高优先级默认键位，避免覆盖写作键位。只修改辅助函数而不修改键位优先级，单元测试虽可通过，浏览器仍会出现旧行为。

## 本地体验

打开 `http://127.0.0.1:4321/studio/?draft=88c6092c-55d7-4353-866b-38f2434c7d49`，标题为“写作体验验收 · 独立测试草稿”。此 ID 仅属于本机，不是服务器草稿。

1. 选一段文字，连续点击两次加粗，确认恢复普通文本；试一次撤销。
2. 在空段落插入代码块，直接输入自己的代码，确认在围栏内。
3. 输入 `1. 第一项`，在末尾连续按两次回车，确认退出列表。
4. 用常用中文输入法实际写一段话，切换候选词并回删；重点观察是否吞字或光标跳动。

本轮相对起点仅改前端编辑器逻辑与测试，没有新增依赖、后端改动或数据库迁移。若后续部署，应按届时确认的提交同步双前端，并保留现有单篇预览后端、私密构件及发布关闭设置。

## 第二轮：图片工作流（同分支，未推送）

- 上传由编辑器内任务队列管理，HTTP 仍使用原 `/studio-api/media/`。无新增依赖、后端或数据库改动。
- 文件选择、粘贴绑定原插入点；文件拖入使用鼠标落点。正文变化通过 CodeMirror ChangeSet 映射任务位置，上传完成不移动当前选区、不主动滚动或抢焦点。
- 批量上传逐张显示等待、上传中、已插入或失败状态；一张失败不阻断后续任务，重试保留原顺序，成功项不重复插入。重试入口只重试指定文件。
- 任务和待重试的 File 对象仅保留在本次编辑器会话中。刷新或离开后需要重新选文件，界面已有提示。编辑器关闭后，迟到的上传结果不会写入下一篇文章。
- 即时渲染时点击图片打开图片设置；所有模式可从“图片管理”选择。支持改说明（Markdown alt）、替换文件、从正文移除及回到图片源码。替换保留说明；移除只删除引用，不删除共享文件，均可撤销。
- 如果原插入点被删除、待替换图片被修改，任务停止并提示重新选择，不覆盖用户新写的正文。
- `tests/studio/image-workflow.test.mjs` 使用实际 EditorState 与可控异步上传验证：等待期间编辑/移动光标、批量失败后继续/重试、原位置删除、替换时并发修改、撤销重做、关闭编辑器后的迟到结果、大小限制以及说明转义。
- 总测试 75/75 通过；普通博客和 Studio 构建成功。
- 浏览器实际验证：修改图片说明、从正文移除及撤销恢复；将浅色图标替换成深色图标后仍保留说明且加载成功；损坏 PNG 与正常 PNG 同批上传，前者报格式错误、后者成功；点击重试重新请求失败图片且正常图片不重复。
- 390×844 模拟手机验证图片管理与设置可用，页面宽度仍为 390。实际系统文件拖放、图片剪贴板及手机系统相册选择仍需对应设备体验；上传慢响应的光标保护由上述可控异步测试验证，不用本机瞬间完成的上传冒充慢网实测。

## 第三轮：表格编辑（同分支，未推送）

- 即时渲染中点击独立表格打开单元格编辑窗口；源码、分屏、预览模式均可从“表格管理”选择。工具栏插入表格也打开同一窗口。
- 第一行为表头；Tab / Shift + Tab 按行切换单元格，边界保留原生焦点导航。支持下方插入行、删除当前内容行、右侧插入列、删除当前列以及默认/左/中/右对齐。表头与最后一列不可删除。
- 修改暂存在窗口内，点击保存后一次写回标准 Markdown，并沿用原草稿自动保存；取消不改变正文。整次保存作为一个撤销步骤。外部点击和 Escape 不会默默丢弃窗口内编辑，可显式点击“取消修改”。
- 保存处理单元格竖线转义，保留代码、链接与列对齐；不使用 HTML 表格替换 Markdown。多行单元格内容规范化为空格。
- 表格位置通过 CodeMirror 变更映射跟踪；其他异步编辑改变前方文本时仍替换正确范围。若原表格已修改则拒绝覆盖，要求重新打开。
- 引用块或列表内的嵌套表格继续源码编辑，不进入独立表格管理，避免丢失引用/缩进前缀。解析器存在差异时回退显示，不阻断整篇编辑器。
- 自动测试覆盖序列化往返、转义竖线/代码/链接、对齐、行列操作、重复表格的范围隔离、并发变更保护、新建分段与撤销重做。总测试 81/81 通过，双前端构建成功。
- 本地浏览器验证 Tab 跨行、增行增列、删除列、取消删除行、保存竖线、源码核对、撤销与重做。390×844 视口下窗口位于页面内（宽 356px），页面宽度 390，Tab 切换与保存对齐通过；实际手机软键盘未代验。
- 本轮继续仅改前端，未增加依赖、更新后端、推送或部署。

## 第四轮：表格窗口内逐步撤销（同分支，未推送）

- 新增独立表格历史，记录单元格内容、增删行列、对齐与当前单元格；窗口内提供撤销/重做按钮，支持 ⌘/Ctrl + Z、⌘/Ctrl + Shift + Z 及 Ctrl + Y。快捷键只影响表格窗口，不触发背后的正文撤销。
- 同一单元格连续同类输入在 800ms 内合并成一步；停顿、切换单元格、光标移动、粘贴或结构操作分开记录。最多保留 100 步，撤销后新编辑清空重做分支，无变化不创建步骤。
- 输入法合成期间不执行撤销，并将一次合成作为一组记录。纯状态测试覆盖合成跨停顿；尚未用真实中文候选词窗口完成端到端验证。
- 保存仍作为正文的一次修改；取消不改变正文，关闭后窗口内历史不持久化，重新打开从当前表格开始。
- 自动测试 87/87 通过，普通博客及 Studio 构建成功。日志：`/private/tmp/wonder-table-history-tests.log`、`/private/tmp/wonder-table-history-blog.log`、`/private/tmp/wonder-table-history-studio.log`。
