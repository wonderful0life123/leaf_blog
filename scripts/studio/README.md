# Wonder 写作空间

本机模式继续使用下文命令。服务器版已增加 GitHub 登录和私有草稿 API，部署与 OAuth 配置请见 [服务器部署说明](../../deploy/studio/DEPLOYMENT.md)。真实 OAuth 配置和服务器上线需要部署方完成；发布到 GitHub 的功能尚未实现。

使用博客原有 Firefly 布局。新建文章、编辑博客副本、选择 Obsidian 笔记导入后，草稿存入独立 SQLite 数据库；不会修改笔记或博客 Markdown 原文件，也不会提交 Git 或发布网站。

## 启动

需要 Node.js 22.13+（当前验证版本 22.23.2），以及项目已安装的依赖。在 leaf_blog 目录执行：

```sh
npm run studio
```

访问 http://127.0.0.1:4321/studio/ 。原 `/admin-prototype/` 会跳转到这里。笔记库默认读取同级 `obsidian_note` 目录。普通 `npm run dev` 不启用写作空间及保存服务。

这是仅供本机使用的开发服务，不是服务器部署方案。GitHub 登录、跨设备草稿、正式构建预览和发布接口尚未实现。不要把开发端口通过代理或隧道公开。

## 编辑体验

打开草稿默认进入专注写作，正文使用居中标准宽度、18px 字号和舒适行距。“Aa 排版”可调整字号、行距和宽屏，偏好保存在当前浏览器；大纲可收起，点击标题可定位正文。工具栏可切换编辑、分屏和预览，顶部“文章设置”展开分类和标签，“退出专注”返回博客布局。

正文使用 CodeMirror Markdown 编辑器，支持语法高亮、撤销重做、列表自动续行、括号配对、Tab 缩进和查找替换。按 Esc 后再按 Tab 可离开编辑器。常用格式按钮作用于当前光标或选区，代码块可选择语言；图片可上传、粘贴或拖入，插入当前光标位置。常用 Markdown 语法和数学公式可预览；这不是 Obsidian 双链或插件系统。撤销历史保留到关闭当前草稿，刷新后以已保存正文重新开始。

## 保存行为

分屏中间的分隔条可拖动，桌面调整左右宽度，手机窄屏调整上下高度。比例记忆在当前浏览器，范围为 25%–75%；双击分隔条或聚焦后按 Enter 恢复均分，方向键也可微调。标题区采用紧凑布局；返回文章列表或退出专注后恢复页面滚动。

- 停止编辑约 600ms 后自动保存标题、正文、分类和标签，也可按 Cmd/Ctrl+S。
- 等待“已保存到本机”后离开。保存失败会明确提示并保留编辑器文字；当前标签页的 sessionStorage 会尽力记录未保存文字，供刷新恢复，但不能代替数据库保存。
- 请求包含草稿版本；另一个页面先保存时，旧页面不能覆盖新版，可以另存草稿副本。
- 上传或粘贴图片支持 PNG/JPEG/GIF/WebP/AVIF，每张最多 10MB，图片本体保存在数据库。
- 导入笔记会解析 Markdown 图片，保存相对路径附件快照；缺失或越界附件会阻止整篇导入并提示。原正文路径保留，通过草稿的图片映射预览，后续原笔记移走也能继续查看。
- 外部 HTTP(S) 图片仍使用外链；HTML 内嵌图片、Obsidian 的 `![[...]]` 附件尚不支持快照转换。
- 重复导入同一来源会打开已有草稿。当前四篇已对应博客的笔记优先打开博客编辑副本，避免覆盖整理后的博客版本。
- Markdown 导出只包含正文和元数据，图片仍在数据库；不是可独立迁移的完整文章包。

## 草稿管理

文章列表可按标题、正文、分类、标签搜索，按最近修改、最近创建或标题排序；展示正文摘要和更新时间。已保存草稿支持复制为独立草稿，图片引用一起保留。

“移入回收站”保留正文和附件引用，恢复后继续编辑。回收站不自动清空，彻底删除需要再次确认，仅删除草稿记录，保留可能共用的图片和已有备份。删除或恢复也检查 revision，防止另一页面覆盖已变化的草稿。仓库原文不被删除；同来源的导入草稿在回收站时需先恢复才能重新打开。

服务器部署请遵循 [草稿管理部署说明](../../deploy/studio/DRAFT_MANAGEMENT.md)：本轮需要同步更新两个后端模块、迁移数据库并重启服务，与之前仅更新前端不同。

## 数据与备份

默认数据位置为 `leaf_blog` 同级目录：

```text
wonder-studio-data/
  studio.sqlite
  studio.sqlite-wal / studio.sqlite-shm   # 运行期间可能出现
  backups/studio-时间-编号.sqlite
```

可用 `WONDER_STUDIO_DATA_DIR=/absolute/path npm run studio` 指定其他位置。数据库独立于 Git 仓库，正文和图片都在其中。不要把数据目录放进 public、src 或其他会同步公开的位置。

有草稿时，每个 UTC 日期首次写入前会保存一个一致性备份。也可随时执行：

```sh
npm run studio:backup
```

若用了自定义数据目录，备份命令也需设置同一个环境变量。手动备份会输出新文件的路径；备份包含所有草稿和图片。备份保存在同一台电脑，不防磁盘丢失，重要内容请将生成的备份复制到自己的安全备份位置。

恢复时先停止写作服务，把整个当前数据目录移动到安全位置留存，再创建数据目录，将选定备份复制并命名为 `studio.sqlite` 后启动。不要在服务运行时替换文件，也不要把旧 WAL/SHM 文件混入恢复后的目录。

## 验证与边界

```sh
npm run studio:test
```

测试覆盖关闭重开、附件独立持久化、版本冲突、失败回滚、路径限制、重复创建、备份恢复以及 HTTP 同源/本机校验。API 位于 `/studio-api/`，遵守站点 trailingSlash 配置。数据服务只在显式启用的 dev 模式注册；生产构建不读取草稿数据库，也不生成写作页面和笔记图片路由。

保存层使用 SQLite WAL + FULL synchronous 和事务；图片 SHA-256 去重；所有草稿更新检查 revision。API 校验 loopback 来源、Host、Origin 和请求大小。以上约束只服务本机阶段，不能替代后续正式认证和授权。

## 发布预览与文章上线

发布流程及服务器接入见 [PUBLISHING.md](../../deploy/studio/PUBLISHING.md)。本机默认只生成私密构建预览；生产必须显式配置独立仓库、基准提交、发布分支和原子切换目录，开启后才允许用户确认提交。草稿 SQLite 当前为 v4（目录与文章绑定）；私密 publications 任务目录也必须备份。完整隔离演练可运行 `node tests/studio/publication-build.smoke.mjs`，它构建两次并仅推送临时本机 Git 仓库。

## 即时渲染编辑

写作区默认使用「即时渲染」，并记住此设备选择的「源码 / 分屏 / 预览」模式。CodeMirror 文档始终是原始 Markdown；光标或选区接触的行恢复语法，其他行显示标题、强调、链接、列表、图片和公式。表格点击后编辑 Markdown 源码，不提供单元格编辑。完整的独立代码块在非编辑状态显示语言标签与高亮卡片，点击恢复源码；未闭合围栏及引用/列表中嵌套的代码块保留源码。代码示例不作为图片或公式渲染；原始 HTML、Obsidian 双链及插件语法保持源码。

IME 合成期间保留并映射现有显示范围，合成结束后再重建，避免重排正在输入的行。自动测试覆盖原文保留、跨段选择、代码保护、图片协议限制、模式切换和撤销；真实中文输入法候选词操作仍需持有人手动验收。上线此编辑器需同步构建两套前端，本功能本身不涉及数据库迁移或额外 API 权限。

### 工作台目录、文件路径与公开归档

工作台目录对应 `src/content/posts` 下 Markdown 的真实层级。文章设置中的“所在目录”、左侧文件树及底部“移动到”面板共享同一位置；标签独立保留。中文目录及中文 Markdown 文件名可用，首次发布可确认文件名，之后修改标题不会自动改名。

移动、新建或重命名目录会立即保存私人期望位置。点击“应用目录调整”先检查公开文章的旧新文件路径及新网址，确认后才批量移动真实 Markdown，并按文件夹更新分类。不发布私人正文、空目录或仅含草稿的子目录。单篇确认发布则携带该文章的正文和当前位置，不连带其他文章的待调整位置。保存草稿始终不执行公开操作。

`articleId` 是独立于可变路径的公开身份。`src/data/article-routes.json` 保存公开文章当前文件位置、路由和历史别名；不包含私人草稿编号。runtime 快照携带相同清单、实际 sourcePath 和 articleId。旧快照保持可读。移动后的旧网址返回站内 302 + no-store，直接跳最新网址；移回旧目录不会形成永久跳转缓存环。静态构建生成相同目标的跳转页面，不承诺静态文件自行返回 302。

共享图片保留原存储位置，改写文章的相对图片和文章链接；代码示例中的路径不改。新版分类从实际文件夹派生，旧 public-archive 映射仅在对应文章明确确认时收拢，不能部署空清单覆盖既有映射。

SQLite v4 是增加式迁移：保留 organization/undo、deleted_at 和所有草稿正文，增加 article_bindings 及 drafts.article_id。存在草稿时先生成一致 SQLite 备份；publications、图片和整个私密数据目录也应独立备份。发布的持久绑定更新不改变私人正文版本。

**最小部署范围（本地确认后另行授权）：**

1. 备份完整私密数据和当前内容版本，暂停新发布，保留 OAuth、环境、图片及历史任务。
2. 按锁文件安装依赖（新增 github-slugger 和 mdast-util-from-markdown），同步本次发布后台模块及共享 src/lib 依赖；Studio、普通博客、runtime 和私密 .studio-preview 构件按同一代码版本生成。只在代码部署时构建，日常目录/文章发布仍走 runtime 快照，不运行 icons/site 全站编译。
3. 发布仓库、代码基准和服务版本保持一致，再启动 Studio 完成迁移；核对既有正文/附件摘要及草稿、回收站记录未变。
4. 用隔离数据完成一次中文路径移动：最终 Git 树旧文章删除、新文章存在，图片字节不变，新 URL 200、旧 URL 302/no-store；确认匿名预览资源仍拒绝。无需重复全部历史浏览器验收。
5. 保持生产发布开关原有意图，由用户验收后决定启用。GitHub 已提交或公开版本已切换时，优先重试原任务完成本地绑定确认；不能用旧数据库覆盖新私人数据，也不能直接回退到缺少新文章/别名的静态版本。

本地验证：`node --test tests/studio/*.test.mjs`、`pnpm build`、`pnpm run studio:build`、`pnpm run runtime:build`、`pnpm run runtime:test`。发布演练仅使用一次性本地裸 Git，覆盖真实目录移动、单篇正文与位置、回移跳转、图片保留和失败重试，不代表生产 GitHub/CDN 已验收。

本地未提交代码体验可用 `WONDER_STUDIO_PREVIEW_REPO_DIR` 指向一次性本机内容快照仓库，配合独立 `WONDER_STUDIO_DATA_DIR`；该选项只用于本机插件，发布保持关闭。不要将它指向生产数据。
